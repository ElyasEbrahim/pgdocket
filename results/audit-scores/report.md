# How many audit labels could the model's scores save?

No API calls. Generated by `jevbench auditscores` (#41). A prediction-powered audit uses each accepted row's score as a control variate. At best that removes the share corr(score, right)² of one label's variance (over the accepted rows), so 1 / (1 − corr²) bounds how many times fewer labels it can need, before the cost of the wider bets it must allow. Drawing the least-sure rows more often is bounded, under calibration, by E[p(1−p)] + var(p) against (E√(p(1−p)))².
